## 1) GPU: hardware specializzato per il rendering

La GPU è la "CPU" della scheda video, con instruction set specializzato.
Caratteristiche chiave:

- architettura a pipeline (catena di montaggio);
- modello SIMD: stesso comando su molti dati in parallelo;
- memoria RAM dedicata a bordo (VRAM);
- copiare dati tra RAM CPU e VRAM e' costoso.

Stima utile per il costo di copia (dipende dalla banda):

$$

T_{copy} = \frac{S}{B}

$$

Dove $S$ è la dimensione dei dati e $B$ la banda di trasferimento.

## 2) PC con scheda video: CPU, GPU, bus e memoria

Schema concettuale:

- la CPU lavora con la RAM di sistema;
- la GPU lavora con la VRAM sulla scheda video;
- comunicano tramite bus, poi la GPU invia il risultato al monitor.

## 3) CPU vs GPU: architettura e potenza di calcolo

Confronto qualitativo:

- CPU: pochi core, tanto controllo e cache;
- GPU: molti core (ALU), poco controllo, altissima parallelizzazione;
- CPU = flessibilità, GPU = potenza (FLOPS).

Definizione di base:

$$

FLOPS = \frac{N_{ops}}{s}

$$

Ordini di grandezza citati:

- GPU moderna: circa $10^{14}$ FLOPS;
- CPU moderna: circa $10^{12}$ FLOPS.

Rapporto tipico:

$$

R = \frac{FLOPS_{GPU}}{FLOPS_{CPU}} \approx \frac{10^{14}}{10^{12}} = 10^2

$$

## 4) Livelli di astrazione: dalla scheda grafica all'applicazione

La catena tipica è:

- Scheda grafica → Driver → API → Librerie/SDK → Applicazione.

Ruoli:

- Driver: traduce le chiamate API verso l'hardware specifico.
- API: interfaccia standard (OpenGL, Direct3D, Vulkan, Metal).
- Librerie: rendono più semplice usare le API (windowing, input, scene utilities).

Nota sulle versioni (come esempio di maturità):

- OpenGL 4.6, Vulkan 1.4, Direct3D 12, Metal 3.

## 5) OpenGL: storia e governance

Punti chiave storici:

- inizialmente sviluppato da Silicon Graphics;
- 2002-2006: OpenGL Architecture Review Board (industria + accademia);
- dal 2006: ARB evolve nel Khronos Group.

Conseguenza:

- specifiche gestite da un consorzio industriale con ampia adozione.

![image.png](GPU,%20Drivers,%20API/image%205.png)

## 6) OpenGL: varianti per embedded e web

Varianti principali:

- OpenGL ES: sottoinsieme per dispositivi embedded;
- WebGL: API per il web, binding JavaScript, basata su OpenGL 3.0 (WebGL 2.0).

Messaggio chiave:

- stessa filosofia, contesti diversi (mobile e browser).

## 7) API grafiche diffuse: Direct3D, Vulkan, Metal

### Direct3D:

- Microsoft, parte di DirectX;
- non cross-platform;
- scopi simili a OpenGL;
- linguaggi C e C++.

### Vulkan (Khronos):

- API a basso livello (simile a Direct3D 12);
- shader in bytecode;
- migliore debugging;
- unified mobile / embedded / desktop.

### Metal (Apple):

- API a basso livello per iOS/macOS/tvOS;
- implementazioni in Swift, Objective-C, C++.

## 8) Librerie e SDK sopra le API

Esempi citati:

- SDL, FreeGLUT, GLFW, SFML, Allegro, Cinder;
- three.js per il web.

Ruolo:

- offrono funzioni di più alto livello (windowing, input, helper grafici);
- riducono il boilerplate rispetto alle API pure.

## 9) Portabilità hardware: stesso software, GPU diverse

Idea mostrata nelle slide:

- lo stesso videogame gira su GPU diverse (es. Nvidia vs AMD);
- cambiano i driver, non il codice applicativo;
- l'API fa da contratto stabile tra software e hardware.

## Riepilogo essenziale

- La GPU è hardware specializzato, con pipeline e SIMD, e VRAM dedicata.
- CPU e GPU hanno architetture diverse: la CPU è flessibile, la GPU è throughput-oriented.
- Driver e API sono livelli chiave per astrarre l'hardware.
- OpenGL ha una lunga storia; le varianti ES e WebGL coprono mobile e web.
- Direct3D, Vulkan e Metal sono alternative diffuse, spesso a basso livello.
- Le librerie (SDL/GLFW/three.js) semplificano l'uso delle API.
- La portabilità nasce dal contratto API/driver: stesso codice, hardware diverso.
